# 6. Conditional Processing

> 이 장에서는 조건 분기, 비교·논리 연산, 반복문, 조건문 구성, 테이블 기반 선택을 다룬다. 어셈블리에서는 비교 결과로 설정된 상태 플래그를 이용해 프로그램의 실행 흐름을 제어한다. 

## 1. 비교 명령어: `CMP`

`CMP`는 목적지에서 원본 값을 빼는 것처럼 동작하여 플래그를 설정하지만, 연산 결과를 저장하거나 피연산자를 변경하지 않는다. 

```asm
cmp eax, ebx
```

이후 조건 분기 명령어는 `CMP`가 설정한 플래그를 확인한다. signed 비교와 unsigned 비교는 같은 값을 비교하더라도 서로 다른 조건 분기 명령어를 사용한다.

## 2. 조건 분기 명령어

| 비교 조건 | unsigned 분기 | signed 분기 |
|---|---|---|
| 같음 | `JE` / `JZ` | `JE` / `JZ` |
| 같지 않음 | `JNE` / `JNZ` | `JNE` / `JNZ` |
| 초과 / 큼 | `JA` | `JG` |
| 크거나 같음 | `JAE` | `JGE` |
| 미만 / 작음 | `JB` | `JL` |
| 작거나 같음 | `JBE` | `JLE` |

- **unsigned 비교**는 주로 `CF`, `ZF`를 사용한다.
- **signed 비교**는 `SF`, `OF`, `ZF`를 조합해 판단한다.
- `JCXZ` / `JECXZ`는 `CX` / `ECX`가 0일 때 분기한다.

```asm
cmp eax, ebx
ja  Above           ; unsigned 비교: EAX > EBX
jg  Greater         ; signed 비교: EAX > EBX
```

> 값이 같을 때는 signed와 unsigned 비교 모두 `JE`를 사용할 수 있다. 어떤 비교를 할지는 데이터가 signed인지 unsigned인지에 따라 선택한다.

## 3. 비트 논리 명령어

| 명령어 | 동작 | 주 용도 |
|---|---|---|
| `AND` | 대응하는 비트가 모두 1일 때 결과 비트가 1 | 비트 검사 및 특정 비트 지우기 |
| `OR` | 대응하는 비트 중 하나라도 1이면 결과 비트가 1 | 특정 비트 설정 |
| `XOR` | 대응하는 비트가 다를 때 결과 비트가 1 | 비트 반전, 패리티 계산, 암호화 |
| `NOT` | 모든 비트를 반전 | 1의 보수 생성 |
| `TEST` | `AND`처럼 플래그를 설정하지만 결과는 저장하지 않음 | 특정 비트가 설정됐는지 검사 |

`AND`, `OR`, `XOR`는 보통 `CF`와 `OF`를 지우고, `SF`, `ZF`, `PF`를 결과에 따라 설정한다. `NOT`은 플래그를 변경하지 않는다. `TEST`는 결과를 저장하지 않고 플래그만 설정한다. 

```asm
and al, 0FCh       ; AL의 하위 두 비트 지우기
or  al, 80h        ; AL의 최상위 비트 설정
xor al, 0FFh       ; AL의 모든 비트 반전
test al, 1         ; 최하위 비트가 설정됐는지 검사
```

`AND`는 비트 마스크를 이용해 원하는 비트를 남기거나 지울 수 있다. `AND`와 `OR`는 비트 집합의 교집합과 합집합 표현에도 사용할 수 있다. 

## 4. 반복문과 조건 반복 명령어

`LOOP`은 `ECX`를 1 감소시키고, 결과가 0이 아니면 지정한 레이블로 분기한다.

```asm
mov ecx, 5
L1:
    ; 반복할 코드
    loop L1
```

| 명령어 | 반복 조건 |
|---|---|
| `LOOP` | `ECX`가 0이 아닐 때 |
| `LOOPE` / `LOOPZ` | `ECX`가 0이 아니고 `ZF = 1`일 때 |
| `LOOPNE` / `LOOPNZ` | `ECX`가 0이 아니고 `ZF = 0`일 때 |

조건 반복 명령어는 `ECX` 값뿐 아니라 `ZF`도 검사한다. 반복문 안에서 플래그가 필요한 경우, 중간 명령어가 플래그를 변경하지 않는지 확인해야 한다. 필요하면 `PUSHFD`와 `POPFD`로 플래그를 보존한다. 

## 5. 조건문 구현

x86 명령어 집합에는 고급 언어의 `if` 문이 직접 있는 것이 아니다. `CMP`와 조건 분기를 조합해 조건문을 만든다. 

```asm
cmp eax, 0
jle LessOrEqual

; EAX > 0일 때 실행할 코드
jmp Done

LessOrEqual:
; EAX <= 0일 때 실행할 코드

Done:
```

MASM은 32비트 모드에서 `.IF`, `.ELSE`, `.ELSEIF`, `.ENDIF` 같은 조건 제어 지시문도 제공한다. 이 지시문은 조건 분기 코드를 생성해 주지만, 해당 고급 조건 제어 지시문은 64비트 모드에서 사용할 수 없다. 

```asm
.IF eax > val1
    mov result, 1
.ELSE
    mov result, 0
.ENDIF
```

## 6. 배열 검색

배열을 순회하며 조건에 맞는 원소를 찾을 수 있다. 예를 들어 각 원소를 0과 비교하여 처음으로 0이 아닌 값을 찾는 방식이다. 

```asm
mov ebx, OFFSET intArray
mov ecx, LENGTHOF intArray

L1:
    cmp WORD PTR [ebx], 0
    jnz Found

    add ebx, TYPE intArray
    loop L1

; 배열에서 값을 찾지 못한 경우
jmp NotFound
```

`EBX`는 현재 원소의 주소를 가리키고, `ECX`는 남은 원소 수를 센다.

## 7. 테이블 기반 선택

테이블 기반 선택(table-driven selection)은 여러 분기 조건을 직접 나열하는 대신, **검색 값과 처리 루틴의 주소를 테이블에 저장**하고 테이블을 검색하는 방법이다. 선택 값이 많을 때 코드 구성을 정리하는 데 유용하다. 

```asm
; 개념 예시
cmp al, [ebx]             ; 입력값과 테이블 값 비교
jne NextEntry

call NEAR PTR [ebx+1]     ; 테이블에 저장된 프로시저 주소 호출
```

## 8. 응용 예시

- `AND`, `OR`, `XOR`를 이용한 비트 집합 연산
- 조건 분기를 이용한 배열 검색과 값 판정
- XOR를 이용한 데이터 암호화와 복호화
- 여러 조건에 따른 등급 판정 및 프로그램 흐름 제어

## 핵심 정리

- `CMP`는 값을 저장하지 않고 비교 결과에 해당하는 플래그를 설정한다.
- signed 비교에는 `JG`, `JL` 등을, unsigned 비교에는 `JA`, `JB` 등을 사용한다.
- `TEST`는 값을 바꾸지 않고 비트 검사 결과만 플래그에 반영한다.
- `LOOP` 계열 명령어는 `ECX`와 조건 플래그를 이용해 반복을 제어한다.
- 조건문은 `CMP`와 조건 분기 명령어를 조합해 구현할 수 있다.
- 테이블 기반 선택은 테이블에 저장된 값과 프로시저 주소를 이용해 여러 선택지를 처리한다.
