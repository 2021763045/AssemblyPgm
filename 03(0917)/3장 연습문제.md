3.9 Review Questions and Exercises
3.9.1 Short Answer
| 번호 | 답 | 풀이 |
|---:|---|---|
| 1 | `MOV`, `ADD`, `SUB` | 명령어 니모닉(mnemonic)의 예시이다. |
| 2 | **호출 규약(Calling Convention)** | 함수 호출 시 인자 전달 순서, 반환값 위치, 스택 정리 담당 등을 정한 규칙이다. 어셈블리 선언에서 `PROC STDCALL`, `PROC C`처럼 사용한다. |
| 3 | `SUB ESP, 크기` | 스택 포인터를 감소시켜 스택 공간을 확보한다. 예: `SUB ESP, 20h` |
| 4 | 정확히는 **assembly language** | “assembler language”는 어셈블러가 사용하는 언어처럼 들린다. 실제로는 사람이 작성하고, 어셈블러가 기계어로 번역하는 언어이므로 assembly language가 더 정확하다. |
| 5 | **Big endian:** 상위 바이트를 낮은 주소에 저장<br>**Little endian:** 하위 바이트를 낮은 주소에 저장 | 예를 들어 `12345678h` 저장 시 Big endian은 `12 34 56 78`, Little endian은 `78 56 34 12` 순서이다. 용어는 조너선 스위프트의 *Gulliver’s Travels*에서 달걀의 큰 쪽(Big-Endians) 또는 작은 쪽(Little-Endians)을 깨는 논쟁에서 유래했다. 컴퓨터 분야에는 Danny Cohen이 1980년에 적용했다. |
| 6 | 의미를 명확히 하고 수정하기 쉽기 때문 | 예: `MAX_SIZE EQU 100`은 코드의 `100`보다 의미가 분명하고, 값 변경도 한 곳에서 가능하다. |
| 7 | **Source file:** 사람이 작성한 어셈블리 원본 파일 (`.asm`)<br>**Listing file:** 어셈블 과정의 주소, 기계어 코드, 소스 등이 함께 표시된 결과 파일 (`.lst`) |
| 8 | **Data label:** 데이터가 저장된 메모리 위치의 이름<br>**Code label:** 실행할 명령어 위치의 이름, 분기·호출 대상에 사용 |
| 9 | **True** | 식별자(identifier)는 숫자로 시작할 수 없다. |
| 10 | **True** | 16진수 리터럴은 `0x3A` 형식으로 작성할 수 있다. |
| 11 | **False** | Directive는 실행 명령어가 아니라, 어셈블러에게 정보를 주는 지시문이다. |
| 12 | **True** | 어셈블리 directive는 일반적으로 대소문자를 구분하지 않는다. |
| 13 | **Label, Mnemonic, Operand, Comment** | 어셈블리 명령어의 기본 구성 요소 4가지이다. |
| 14 | **True** | `MOV`는 데이터를 복사하는 명령어 니모닉이다. |
| 15 | **True** | 코드 레이블은 보통 `L1:`처럼 콜론을 붙이고, 데이터 레이블은 `var1 DWORD 10`처럼 콜론 없이 작성한다. |
| 16 | 예시 | `COMMENT !`<br>`이 부분은 여러 줄 주석입니다.`<br>`!` |
| 17 | 주소가 변경될 수 있기 때문 | 숫자 주소를 직접 사용하면 변수 위치가 바뀔 때 코드를 모두 수정해야 한다. 데이터 레이블을 사용하면 가독성과 유지보수성이 좋아진다. |
| 18 | **32비트 종료 코드(DWORD)** | `ExitProcess`에는 프로그램의 종료 상태 코드(exit code)를 인자로 전달한다. 예: `INVOKE ExitProcess, 0` |
| 19 | **`ENDP`** | 프로시저의 끝을 표시한다. 예: `main ENDP` |
| 20 | **프로그램의 시작 지점(entry point)을 지정** | 예: `END main`에서 `main`은 실행이 시작될 프로시저를 나타낸다. |
| 21 | **프로시저 원형(prototype) 선언** | 프로시저 이름, 매개변수 자료형 등을 미리 선언하여 올바른 호출인지 확인하게 한다. |
| 22 | **False** | Object file(`.obj`)은 **Assembler**가 만든다. Linker는 이를 연결하여 실행 파일을 만든다. |
| 23 | **True** | Listing file(`.lst`)은 Assembler가 생성한다. |
| 24 | **True** | Link library(`.lib`)는 Linker가 실행 파일을 만들기 직전에 프로그램에 연결한다. |
| 25 | **`SDWORD`** | 32비트 부호 있는 정수 변수를 만든다. |
| 26 | **`SWORD`** | 16비트 부호 있는 정수 변수를 만든다. |
| 27 | **`QWORD`** | 64비트 부호 없는 정수 변수를 만든다. |
| 28 | **`SBYTE`** | 8비트 부호 있는 정수 변수를 만든다. |
| 29 | **`TBYTE`** | 10바이트 packed BCD 변수를 만든다. |

## 3. Doubleword를 Big Endian 형식으로 메모리에 저장

```asm
bigEndian DWORD 78563412h
```

위 값은 메모리에 다음과 같이 저장된다.

```text
12 34 56 78
```

x86은 Little Endian 시스템이므로, 메모리에 `12 34 56 78` 순서로 저장하려면 값을 뒤집어 `78563412h`로 선언해야 한다.

## 4. DWORD 변수에 음수값 할당 가능 여부

```asm
value DWORD -1
```

가능하다.

이는 `DWORD`가 32비트 크기를 지정할 뿐, signed/unsigned 여부를 엄격하게 검사하지 않는다는 것을 의미한다.

## 5. EAX와 EDX에 5를 더하는 명령어 비교

```asm
add eax, 5
add edx, 5
```

Listing file에서 확인할 수 있는 기계어 코드 예시는 다음과 같다.

| 명령어 | 기계어 코드 |
|---|---|
| `add eax, 5` | `83 C0 05` |
| `add edx, 5` | `83 C2 05` |

두 명령어 모두 3바이트이다.  
차이점은 레지스터를 나타내는 바이트뿐이다.

- `C0`: `EAX`
- `C2`: `EDX`

## 1. 정수식 계산 프로그램

식:

$$A = (A + B) - (C + D)$$

```asm
INCLUDE Irvine32.inc

.code
main PROC
    ; A = EAX, B = EBX, C = ECX, D = EDX
    mov eax, 20        ; A = 20
    mov ebx, 10        ; B = 10
    mov ecx, 5         ; C = 5
    mov edx, 3         ; D = 3

    add eax, ebx       ; EAX = A + B = 30
    add ecx, edx       ; ECX = C + D = 8
    sub eax, ecx       ; EAX = (A + B) - (C + D) = 22

    call DumpRegs
    exit
main ENDP

END main
```

최종 결과는 `EAX = 22`이다.

## 5. AddTwoSum 프로그램의 Listing File 분석

예제 코드:

```asm
INCLUDE Irvine32.inc

.data
sum DWORD ?

.code
main PROC
    mov eax, 5
    add eax, 6
    mov sum, eax

    call DumpRegs
    exit
main ENDP

END main
```

주요 명령어의 기계어 코드 예시는 다음과 같다.

| 어셈블리 명령어 | 기계어 코드 예시 | 설명 |
|---|---|---|
| `mov eax, 5` | `B8 05 00 00 00` | `B8`은 `EAX`에 즉시값을 저장하는 opcode이고, 뒤의 4바이트는 숫자 `5`이다. |
| `add eax, 6` | `83 C0 06` | `83`은 즉시값 덧셈 opcode, `C0`은 `EAX`, `06`은 숫자 `6`이다. |
| `mov sum, eax` | `A3 xx xx xx xx` | `A3`은 `EAX` 값을 메모리에 저장하는 opcode이다. `xx` 부분은 `sum`의 주소이다. |
| `call DumpRegs` | `E8 xx xx xx xx` | `E8`은 프로시저 호출 opcode이며, 뒤의 값은 `DumpRegs`까지의 상대 주소이다. |
| `exit` | `6A 00`, `FF 15 ...` 등 | `ExitProcess`를 호출하여 프로그램을 종료한다. 실제 코드는 라이브러리 및 빌드 설정에 따라 달라질 수 있다. |

> Listing file에서는 명령어의 메모리 주소, 기계어 코드, 원본 어셈블리 코드를 함께 확인할 수 있다.

## 6. AddVariables 프로그램을 64비트 변수로 변경

기존 32비트 변수 예시:

```asm
.data
firstVal  DWORD 20000000h
secondVal DWORD 11111111h
thirdVal  DWORD 22222222h
sum       DWORD 0
```

64비트 변수로 변경한 코드:

```asm
.data
firstVal  QWORD 2000000000000000h
secondVal QWORD 1111111111111111h
thirdVal  QWORD 2222222222222222h
sum       QWORD 0

.code
main PROC
    mov rax, firstVal
    add rax, secondVal
    add rax, thirdVal
    mov sum, rax

    exit
main ENDP

END main
```

### 발생 가능한 오류와 해결 방법

| 문제 | 원인 | 해결 방법 |
|---|---|---|
| Operand size conflict | `QWORD` 변수에 32비트 레지스터인 `EAX`를 사용함 | 64비트 레지스터인 `RAX`를 사용 |
| 64비트 레지스터 인식 오류 | 32비트 프로젝트에서 `RAX`를 사용함 | 64비트 프로젝트 또는 `ml64.exe` 사용 |
| 라이브러리 연결 오류 | 32비트용 Irvine 라이브러리를 연결함 | 64비트용 라이브러리와 설정 사용 |

핵심은 다음과 같다.

```text
DWORD → QWORD
EAX   → RAX
```

즉, 64비트 변수를 사용할 때는 이에 맞는 64비트 레지스터와 64비트 빌드 환경을 사용해야 한다.
