# 4.9 Review Questions and Exercises
4.9.1 Short Answer

## 1. `MOVSX` 실행 후 EDX 값

```asm
.data
one WORD 8002h
two WORD 4321h

.code
mov   edx, 21348041h
movsx edx, one            ; (a)
movsx edx, two            ; (b)
```

### (a) `movsx edx, one`

`one`의 값은 `8002h`이다.

- `WORD`는 16비트이다.
- 최상위 비트가 `1`이므로 signed 값에서는 음수이다.
- `MOVSX`는 부호 확장(sign extension)을 수행한다.

```text
8002h → FFFF8002h
```

따라서:

```text
EDX = FFFF8002h
```

### (b) `movsx edx, two`

`two`의 값은 `4321h`이다.

- 최상위 비트가 `0`이므로 양수이다.
- 상위 비트는 모두 `0`으로 확장된다.

```text
4321h → 00004321h
```

따라서:

```text
EDX = 00004321h
```

## 2. `INC AX` 실행 후 EAX 값

```asm
mov eax, 1002FFFFh
inc ax
```

초기값:

```text
EAX = 1002FFFFh
```

`AX`는 EAX의 하위 16비트이다.

```text
AX = FFFFh
```

`FFFFh`에 1을 더하면:

```text
FFFFh + 1 = 0000h
```

상위 16비트는 변하지 않는다.

```text
EAX = 10020000h
```

**정답:**

```text
EAX = 10020000h
```

```text
0000h - 1 = FFFFh
```

상위 16비트는 유지된다.

```text
EAX = 3002FFFFh
```

**정답:**

```text
EAX = 3002FFFFh
```

## 4. `NEG AX` 실행 후 EAX 값


```text

```

`NEG`는 2의 보수(two's complement)를 이용하여 부호를 반전한다.

```text
-FFFFh = 0001h
```

상위 16비트는 변하지 않는다.

```text
EAX = 10020001h
```

**정답:**

```text
EAX = 10020001h
```

## 5. 덧셈 후 Parity Flag 값

```asm
mov al, 1
add al, 3
```

계산 결과:

```text
AL = 1 + 3 = 4
```

2진수로 표현하면 다음과 같다.

```text
4 = 00000100b
```

`1`의 개수는 1개이며 홀수이다.

Parity Flag는 결과의 하위 바이트에서 `1`의 개수가 짝수일 때 설정된다.

```text
PF = 0
```

**정답:**

```text
AL = 04h
Parity Flag = 0
```

## 7. Overflow Flag와 signed byte 범위

```asm
mov al, -1
add al, 130
```

초기값:

```text
AL = -1 = FFh
```

`130`의 16진수 값은 `82h`이다.

```text
FFh + 82h = 181h
```

AL은 8비트 레지스터이므로 하위 8비트만 저장된다.

```text
AL = 81h
```

`81h`를 signed byte로 해석하면 다음과 같다.

```text
81h = -127
```

하지만 원래 signed 연산 결과는 다음과 같다.

```text
-1 + 130 = 129
```

signed byte의 범위는 다음과 같다.

$$-128 \leq x \leq 127$$

`129`는 signed byte 범위를 초과하므로 **Overflow Flag가 설정된다.**

```text
OF = 1
```

따라서 AL에 저장된 `-127`은 실제 계산 결과가 아니라, 오버플로로 인해 값이 순환(wrap-around)된 결과이다.

**정답:**

```text
AL = 81h = -127
Overflow Flag = 1
```

> Overflow Flag가 `1`이면 signed 연산의 실제 결과가 해당 자료형의 유효 범위를 벗어났다는 의미이다.


## 12. 양수와 음수를 더할 때 Overflow Flag 설정 가능 여부

> 양수와 음수를 더하여 Overflow Flag를 설정할 수 있는가?

**정답: No**

Signed 연산에서 Overflow는 같은 부호의 두 값을 더했을 때 발생한다.

- 양수 + 양수 → 음수가 되면 Overflow
- 음수 + 음수 → 양수가 되면 Overflow
- 양수 + 음수 → Overflow 발생하지 않음

---

## 13. 음수와 음수를 더해서 양수가 되면 Overflow Flag 설정 여부

> 음수와 음수를 더했는데 양수 결과가 나오면 Overflow Flag가 설정되는가?

**정답: Yes**

음수 두 개를 더한 결과가 양수가 되면 signed 범위를 벗어난 것이므로 Overflow Flag가 설정된다.

```text
OF = 1
```

---

## 14. `NEG` 명령어가 Overflow Flag를 설정할 수 있는가?

**정답: Yes**

가장 작은 signed 정수를 음수로 바꾸려고 할 때 Overflow가 발생한다.

예를 들어 8비트 signed 정수에서:

```text
-128 = 80h
```

`-(-128)`은 `+128`이어야 하지만 signed byte의 최대값은 `+127`이다.

```asm
mov al, 80h
neg al
```

따라서:

```text
OF = 1
```

---

## 15. Sign Flag와 Zero Flag를 동시에 설정할 수 있는가?

> Sign Flag와 Zero Flag가 동시에 `1`이 될 수 있는가?

**정답: No**

- **Zero Flag (`ZF`)**: 연산 결과가 `0`이면 `1`
- **Sign Flag (`SF`)**: 연산 결과의 최상위 비트가 `1`, 즉 음수이면 `1`

결과가 `0`일 때 모든 비트는 `0`이므로 최상위 비트도 `0`이다.

```text
결과 = 00000000h
ZF = 1
SF = 0
```

반대로 음수 결과에서는 최상위 비트가 `1`이므로 결과가 `0`일 수 없다.

따라서 다음 상태는 불가능하다.

```text
SF = 1
ZF = 1
```

# 16. 명령어 유효성 판단

사용할 변수 정의:

```asm
.data
var1 SBYTE -4, -2, 3, 1
var2 WORD 1000h, 2000h, 3000h, 4000h
var3 SWORD -16, -42
var4 DWORD 1, 2, 3, 4, 5
```

| 항목 | 명령어 | 유효 여부 | 이유 |
|---|---|---|---|
| a | `mov ax, var1` | Invalid | `AX`는 16비트지만 `var1`은 8비트이다. |
| b | `mov ax, var2` | Valid | `AX`와 `var2`는 모두 16비트이다. |
| c | `mov eax, var3` | Invalid | `EAX`는 32비트지만 `var3`은 16비트이다. |
| d | `mov var2, var3` | Invalid | 메모리에서 메모리로 직접 `MOV`할 수 없다. |
| e | `movzx ax, var2` | Invalid | `MOVZX`는 작은 크기의 값을 더 큰 크기의 레지스터로 확장할 때 사용한다. 16비트 값을 16비트 `AX`로 확장할 수 없다. |
| f | `movzx var2, al` | Invalid | `MOVZX`의 목적지는 반드시 레지스터여야 한다. |
| g | `mov ds, ax` | Valid | 세그먼트 레지스터 `DS`에는 16비트 레지스터 값을 저장할 수 있다. |
| h | `mov ds, 1000h` | Invalid | 세그먼트 레지스터에는 즉시값을 직접 저장할 수 없다. |

`DS`에 즉시값을 저장하려면 다음처럼 작성해야 한다.

```asm
mov ax, 1000h
mov ds, ax
```

## 17. 각 명령어 실행 후 목적지 값

```asm
mov al, var1          ; a.
mov ah, [var1+3]      ; b.
```

`var1`의 값:

```text
var1 = -4, -2, 3, 1
```

16진수 바이트 값:


| 항목 | 명령어 | 목적지 값 |
|---|---|---|
| a | `mov al, var1` | `AL = FCh` |
| b | `mov ah, [var1+3]` | `AH = 01h` |

두 명령어를 순서대로 실행한 후 `AX` 값은 다음과 같다.

```text
AX = 01FCh
```

## 18. 각 명령어 실행 후 AX 값

```asm
mov ax, var2          ; a.
mov ax, [var2+4]      ; b.
mov ax, var2-2        ; c.
mov ax, [var3-2]      ; d.
```

`var2`의 값:

```text
1000h, 2000h, 3000h, 4000h
```

| 항목 | 명령어 | AX 값 | 설명 |
|---|---|---|---|
| a | `mov ax, var2` | `1000h` | 첫 번째 WORD 값을 읽는다. |
| b | `mov ax, [var2+4]` | `3000h` | WORD는 2바이트이므로 `+4`는 세 번째 요소이다. |
| c | `mov ax, var2-2` | `0103h` | `var2` 바로 앞의 두 바이트는 `var1`의 `03h`, `01h`이다. |
| d | `mov ax, [var3-2]` | `4000h` | `var3` 바로 앞에는 `var2`의 마지막 값 `4000h`가 있다. |

## 19. 각 명령어 실행 후 EDX 값

```asm
mov edx, var4         ; a.
movzx edx, var2       ; b.
mov edx, [var4+4]     ; c.
movsx edx, var1       ; d.
```

| 항목 | 명령어 | EDX 값 | 설명 |
|---|---|---|---|
| a | `mov edx, var4` | `00000001h` | `var4`의 첫 번째 DWORD 값은 1이다. |
| b | `movzx edx, var2` | `00001000h` | `1000h`를 32비트로 zero-extension한다. |
| c | `mov edx, [var4+4]` | `00000002h` | 두 번째 DWORD 값은 2이다. |
| d | `movsx edx, var1` | `FFFFFFFCh` | `-4`를 32비트로 sign-extension한다. |

## 8. DWORD 배열의 합 계산


## 11. `INC`와 `DEC`에서 Zero Flag를 이용한 범위 확인

### `INC` 수행 후 unsigned overflow 확인

```asm
mov al, 0FFh
inc al

jz UnsignedOverflow
```

`FFh`에 1을 더하면 `00h`가 된다.

```text
AL = 00h
ZF = 1
```

따라서 `ZF = 1`이면 unsigned overflow가 발생한 것이다.

### `DEC` 수행 후 0 확인

```asm
mov al, 1
dec al

jz ReachedZero
```

```text
AL = 00h
ZF = 1
```

`DEC` 후 `ZF = 1`이면 값이 0에 도달했음을 의미한다. 다음 `DEC` 연산을 실행하면 unsigned underflow가 발생할 수 있다.

`LABEL DWORD`는 `myWords` 주소의 자료형을 DWORD로 해석하도록 한다.

## 18. `myBytes`를 16비트 레지스터로 직접 이동하도록 `LABEL` 선언

```asm
.data
myBytes LABEL WORD
        BYTE 10h, 20h, 30h, 40h

myWords WORD 3 DUP(?), 2000h
myString BYTE "ABC"
```

이후 다음과 같이 사용할 수 있다.

```asm
mov ax, myBytes
```

## 1. Big Endian을 Little Endian으로 변환

`bigEndian`에 저장된 바이트 순서는 `12h, 34h, 56h, 78h`이다.  
이를 `littleEndian`에 역순으로 복사하여 최종적으로 `12345678h` 값이 되도록 한다.

```asm
INCLUDE Irvine32.inc

.data
bigEndian    BYTE 12h, 34h, 56h, 78h
littleEndian DWORD ?

.code
main PROC
    mov al, bigEndian
    mov BYTE PTR littleEndian+3, al

    mov al, bigEndian+1
    mov BYTE PTR littleEndian+2, al

    mov al, bigEndian+2
    mov BYTE PTR littleEndian+1, al

    mov al, bigEndian+3
    mov BYTE PTR littleEndian, al

    ; littleEndian의 값: 12345678h

    exit
main ENDP

END main
```

최종 메모리 순서:

```text
littleEndian: 78h, 56h, 34h, 12h
```

## 2. 배열의 인접한 값 쌍 교환

예를 들어 배열이 다음과 같다고 가정한다.

```text
[10, 20, 30, 40, 50, 60]
```

실행 후 결과:

```text
[20, 10, 40, 30, 60, 50]
```

```asm
INCLUDE Irvine32.inc

.data
array DWORD 10, 20, 30, 40, 50, 60

.code
main PROC
    mov ecx, LENGTHOF array / 2
    mov esi, 0

L1:
    mov eax, array[esi * TYPE array]
    xchg eax, array[esi * TYPE array + TYPE array]
    mov array[esi * TYPE array], eax

    add esi, 2
    loop L1

    exit
main ENDP

END main
```

## 3. 배열 원소 사이의 차이 합계 계산

예제 배열:

```text
[0, 2, 5, 9, 10]
```

각 차이:

```text
2 - 0 = 2
5 - 2 = 3
9 - 5 = 4
10 - 9 = 1
```

합계:

```text
2 + 3 + 4 + 1 = 10
```

```asm
INCLUDE Irvine32.inc

.data
array DWORD 0, 2, 5, 9, 10
sum   DWORD ?

.code
main PROC
    mov eax, 0                  ; 차이의 합계
    mov ebx, array              ; 이전 배열 원소
    mov esi, 1
    mov ecx, LENGTHOF array - 1

L1:
    mov edi, array[esi * TYPE array]
    mov edx, edi
    sub edx, ebx                ; 현재 원소 - 이전 원소
    add eax, edx                ; 합계에 추가

    mov ebx, edi                ; 현재 원소를 이전 원소로 변경
    inc esi
    loop L1

    mov sum, eax                ; sum = 10

    exit
main ENDP

END main
```

## 4. WORD 배열을 DWORD 배열로 복사

`WORD`는 16비트이고 `DWORD`는 32비트이다.  
부호 없는 값이므로 `MOVZX`를 사용하여 상위 비트를 `0`으로 확장한다.

```asm
INCLUDE Irvine32.inc

.data
source WORD 1000h, 2000h, 3000h, 4000h
target DWORD LENGTHOF source DUP(?)

.code
main PROC
    mov esi, 0
    mov ecx, LENGTHOF source

L1:
    movzx eax, WORD PTR source[esi * TYPE source]
    mov target[esi * TYPE target], eax

    inc esi
    loop L1

    exit
main ENDP

END main
```

복사 결과:

```text
target = 00001000h, 00002000h, 00003000h, 00004000h
```

## 5. 피보나치 수열의 처음 7개 값 계산

피보나치 수열:

```text
1, 1, 2, 3, 5, 8, 13
```

```asm
INCLUDE Irvine32.inc

.data
fib DWORD 7 DUP(?)

.code
main PROC
    mov fib, 1
    mov fib + TYPE fib, 1

    mov eax, 1                  ; Fib(n - 2)
    mov ebx, 1                  ; Fib(n - 1)

    mov esi, 2
    mov ecx, LENGTHOF fib - 2

L1:
    mov edx, eax
    add edx, ebx                ; 새 피보나치 값 계산

    mov fib[esi * TYPE fib], edx

    mov eax, ebx
    mov ebx, edx

    inc esi
    loop L1

    exit
main ENDP

END main
```

최종 배열:

```text
fib = 1, 1, 2, 3, 5, 8, 13
```

## 6. 배열을 제자리에서 역순으로 변경

별도의 배열을 만들지 않고, 원본 배열 내부에서 첫 번째와 마지막 원소를 교환한다.

```asm
INCLUDE Irvine32.inc

.data
array DWORD 10, 20, 30, 40, 50, 60

.code
main PROC
    mov esi, 0
    mov edi, SIZEOF array - TYPE array
    mov ecx, LENGTHOF array / 2

L1:
    mov eax, array[esi]
    xchg eax, array[edi]
    mov array[esi], eax

    add esi, TYPE array
    sub edi, TYPE array
    loop L1

    exit
main ENDP

END main
```

실행 전:

```text
[10, 20, 30, 40, 50, 60]
```

실행 후:

```text
[60, 50, 40, 30, 20, 10]
```

## 7. 문자열을 역순으로 복사

`source` 문자열을 `target`으로 복사하되, 문자 순서를 반대로 저장한다.

```asm
INCLUDE Irvine32.inc

.data
source BYTE "This is the source string", 0
target BYTE SIZEOF source DUP('#')

.code
main PROC
    mov esi, OFFSET source + SIZEOF source - 2
    mov edi, OFFSET target
    mov ecx, SIZEOF source - 1

L1:
    mov al, [esi]
    mov [edi], al

    dec esi
    inc edi
    loop L1

    mov BYTE PTR [edi], 0

    exit
main ENDP

END main
```

실행 후 `target` 문자열:

```text
gnirts ecruos eht si sihT
```

## 8. 배열 원소를 오른쪽으로 한 칸 회전

예제 배열:

```text
[10, 20, 30, 40]
```

실행 후 결과:

```text
[40, 10, 20, 30]
```

```asm
INCLUDE Irvine32.inc

.data
array DWORD 10, 20, 30, 40

.code
main PROC
    ; 마지막 원소를 보관
    mov eax, array[SIZEOF array - TYPE array]

    ; 마지막 위치부터 두 번째 위치까지 이동
    mov esi, SIZEOF array - TYPE array
    mov ecx, LENGTHOF array - 1

L1:
    mov edx, array[esi - TYPE array]
    mov array[esi], edx

    sub esi, TYPE array
    loop L1

    ; 원래 마지막 원소를 첫 번째 위치에 저장
    mov array, eax

    exit
main ENDP

END main
```

실행 과정:

```text
초기 배열: [10, 20, 30, 40]
마지막 값 보관: 40

최종 배열: [40, 10, 20, 30]
```
