# 8. Advanced Procedures

## 개요

이 장에서는 프로시저에 인자를 전달하고 결과를 반환하는 방법, 스택 프레임과 지역 변수 관리, 재귀 호출, 여러 소스 모듈에서 프로시저를 연결하는 방법을 다룬다. 프로시저를 만들고 호출하는 문법뿐 아니라 호출 규약과 레지스터 보존 규칙도 함께 살펴본다.

## 1. 스택 프레임

스택 프레임은 프로시저 실행 중 필요한 정보가 저장되는 스택 영역이다. 일반적으로 파라미터, 반환 주소, 저장된 레지스터와 지역 변수가 포함된다. 지역 변수는 런타임 스택에 생성되며, 보통 `EBP`를 기준으로 접근한다. 

표준 스택 프레임은 다음과 같은 형태다.

```text
[EBP+12]  두 번째 파라미터
[EBP+8]   첫 번째 파라미터
[EBP+4]   반환 주소
[EBP]     호출자의 EBP
[EBP-4]   지역 변수
```

스택은 낮은 주소 방향으로 자란다. 프로시저가 끝날 때 `ESP`를 `EBP` 기준 위치로 되돌리면 지역 변수 공간을 해제할 수 있다. `ENTER`는 스택 프레임을 만들고 지역 변수 공간을 확보하며, `LEAVE`는 이를 해제한다. 

## 2. 파라미터 전달과 호출 규약

파라미터는 스택이나 레지스터를 통해 전달할 수 있다. 파라미터는 호출자에서 프로시저로 전달되는 데이터 방향에 따라 입력, 출력, 입력·출력 파라미터로 구분한다. 배열이나 구조체처럼 큰 데이터는 일반적으로 실제 데이터를 복사하기보다 주소를 전달한다. 

### STDCALL

`STDCALL`에서는 호출된 프로시저가 파라미터에 사용된 스택 공간을 정리한다. 예를 들어 파라미터가 총 8바이트라면 `RET 8`을 사용한다. 

### C 호출 규약

C 호출 규약에서는 호출한 쪽이 파라미터 스택 공간을 정리한다. 이 방식은 파라미터 개수가 달라질 수 있는 함수에 활용하기 쉽다.

### FASTCALL

32비트 `FASTCALL`은 일부 파라미터를 레지스터로 전달할 수 있다. 다만 사용한 레지스터를 저장하고 복원하는 과정이 추가되면, 성능상 이점이 줄어들 수 있다. 

## 3. PROC, PROTO, INVOKE, ADDR

### PROC

`PROC`는 프로시저를 정의하며, 이름이 있는 파라미터를 선언할 수 있다.

```asm
AddThree PROC, a:DWORD, b:DWORD, c:DWORD
    mov eax, a
    add eax, b
    add eax, c
    ret
AddThree ENDP
```

`USES`를 함께 사용하면 프로시저에서 변경하는 레지스터를 저장하고 복원하도록 지정할 수 있다.

```asm
ArraySum PROC USES esi ecx, pArray:PTR DWORD, count:DWORD
    ; 프로시저 본문
    ret
ArraySum ENDP
```

### PROTO

`PROTO`는 프로시저의 이름과 파라미터 형식을 미리 선언한다. 실제 정의와 호출부를 서로 다른 위치나 소스 모듈에 둘 때 사용한다.

```asm
ArraySum PROTO, pArray:PTR DWORD, count:DWORD
```

### INVOKE

`INVOKE`는 파라미터 전달과 `CALL`을 간단히 작성하게 해준다. 호출 규약에 맞는 인자 순서와 스택 처리를 지원한다. 

```asm
INVOKE ArraySum, ADDR numbers, LENGTHOF numbers
```

### ADDR

`ADDR`은 `INVOKE`에서 변수나 배열의 주소를 파라미터로 전달할 때 사용한다. 주소를 넘기는 프로시저에서는 실제 값과 주소를 혼동하지 않도록 주의해야 한다. 

## 4. 지역 변수와 참조 파라미터

`LOCAL`은 스택 프레임 안에 이름과 자료형을 가진 지역 변수를 만든다.

```asm
MyProc PROC
    LOCAL total:DWORD
    LOCAL buffer[20]:BYTE

    mov total, 0
    ret
MyProc ENDP
```

지역 변수는 프로시저가 실행되는 동안에만 존재한다. 프로시저가 끝나면 스택 프레임이 해제되므로 지역 변수 공간도 함께 사라진다. `LOCAL`은 이름과 크기가 있는 변수를 선언하고, `ENTER`는 이름이 없는 스택 공간을 확보한다. 

참조 파라미터는 데이터 자체가 아니라 데이터가 저장된 주소를 받는다. 프로시저는 보통 포인터와 `EBP` 기준 주소 지정 방식을 이용해 해당 데이터를 읽거나 수정한다. 잘못된 주소를 참조하면 잘못된 메모리 접근이 발생할 수 있다. 

## 5. 재귀 프로시저

재귀 프로시저는 실행 중 자신을 다시 호출한다. 각 호출은 별도의 스택 프레임을 만들기 때문에, 이전 호출의 파라미터와 임시 데이터가 다음 호출에 의해 덮어쓰이지 않는다. 재귀 호출이 끝나면 스택 프레임을 차례로 복원하면서 저장해 둔 값을 사용할 수 있다. 

재귀 프로시저를 작성할 때는 다음 두 가지를 명확히 해야 한다.

1. 재귀를 멈출 **기저 조건**
2. 입력을 줄여 다음 호출로 전달하는 **재귀 단계**

## 6. 여러 소스 모듈에서 프로시저 사용하기

프로그램을 여러 소스 파일로 나누면 프로시저를 별도 모듈에 정의하고 다른 모듈에서 호출할 수 있다.

| 지시어 | 용도 |
|---|---|
| `PUBLIC` | 다른 모듈에서 사용할 이름을 공개 |
| `EXTERN` | 다른 모듈에 정의된 이름을 선언 |
| `EXTERNDEF` | `PUBLIC`과 `EXTERN`의 역할을 함께 처리 |

기본적으로 이름은 해당 모듈 안에서 사용된다. 외부 모듈에서 사용할 프로시저나 심볼은 공개 범위를 명시해야 한다. `EXTERN`으로 외부 프로시저를 선언할 때는 이름 장식과 파라미터 크기 정보가 필요할 수 있다. 

## 7. 디버깅 도구

Irvine32 라이브러리의 `WriteStackFrame`은 현재 프로시저의 스택 프레임을 출력한다. 파라미터, 반환 주소, 지역 변수, 저장된 레지스터의 위치를 확인할 때 유용하다. 

## 구현 시 주의사항

- 호출 규약에 따라 스택을 정리하는 쪽이 달라진다.
- `USES`에 지정한 레지스터와 직접 저장·복원하는 레지스터를 관리한다.
- 주소를 받아야 하는 파라미터에는 값이 아닌 포인터를 전달한다.
- 지역 변수는 프로시저 실행이 끝나면 사용할 수 없다.
- 재귀 호출은 기저 조건과 스택 사용량을 함께 확인한다.
- 여러 모듈에서 사용할 프로시저는 `PROTO`, `PUBLIC`, `EXTERN` 선언을 맞춘다.
- 스택 프레임을 점검할 때는 파라미터, 반환 주소, 저장된 `EBP`, 지역 변수의 위치를 구분한다.

## 핵심 요약

`PROC`와 `PROTO`로 프로시저의 인터페이스를 정의하고, `INVOKE`와 `ADDR`로 인자를 전달한다. 스택 프레임은 파라미터와 지역 변수의 위치를 관리하며, 호출 규약은 인자 전달과 스택 정리 방식을 결정한다. 이 규칙을 지키면 재귀 프로시저와 여러 소스 모듈로 구성된 프로그램을 더 안정적으로 작성할 수 있다.
